# Rubric — LAB-702 Controlled object allocation

Score each dimension 0–100, then apply the weight. A faster `die` run that claims “records never allocate” is not a high Technical score.

| Dimension | Weight | 100 | 60 | 20 |
|---|---|---|---|---|
| Technical accuracy | 25% | Both modes, same N; retain live set vs die garbage; records still allocate; strings named | Both ran; comparison thin or one mode missing numbers | One mode only, or “JIT deletes all allocations” |
| Diagnostic method | 20% | Count, elapsed, used-heap (or honest noise) recorded before conclusions | Times without used-heap | No numbers |
| Production awareness | 15% | Relates Payment-like / Money-like to BayPay money types; `Pay1` same rules | Mentions payments | Puzzle-only; cloud load test |
| Trade-off analysis | 15% | Escape analysis **might** scalar-replace; “does not always”; when retain is intentional | Mentions JIT or GC once | No trade-off |
| Security / reliability | 10% | `dieSink` / anti-DCE understood; no `double` money sermon required; no secret data | Harmless | Invents a leak RCA from one die delta |
| Communication | 10% | Two stdout blocks + paragraph | Times without modes labeled | Empty notes |
| Efficiency | 5% | Starter compile `--release 21`; local `$0` | Extra unused profiler | AWS or JFR required in the write-up |

**Pass guideline:** weighted score ≥ 70, both modes evidenced, and escape analysis is not stated as a guarantee.
