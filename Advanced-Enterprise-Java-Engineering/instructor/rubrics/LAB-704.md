# Rubric — LAB-704 JVM and container memory experiment

Score each dimension 0–100, then apply the weight. Docker absence must not fail the lab. `-Xmx` equal to the 512 MiB limit cannot score high on Technical or Production.

| Dimension | Weight | 100 | 60 | 20 |
|---|---|---|---|---|
| Technical accuracy | 25% | 512 × 25% = 128 MiB and 512 × 75% = 384 MiB (or byte-accurate); heap ≠ cgroup; four+ native consumers | Percentages close; weak sum | Host ergonomics as the 512 answer; heap = 512m |
| Diagnostic method | 20% | Multiplication shown; convention stated; Docker labeled optional / unused | Answers without showing work | Solution arithmetic only |
| Production awareness | 15% | Cgroup kill vs Java heap OOM; same rule on `Pay1`; no new ND cell; no AWS/K8s required | Mentions OOM | Recommends heap = limit or a cluster |
| Trade-off analysis | 15% | 75% vs lower when threads/direct grow; `%` vs explicit `-Xmx384m` | One honest trade-off | None |
| Security / reliability | 10% | Native headroom as reliability; no “just raise the limit” as the only fix | Mentions headroom | Ignores kernel kill |
| Communication | 10% | Worksheet container section with arithmetic and flags | Flags without math | Empty |
| Efficiency | 5% | Paper path, `$0`; Docker extra only | Docker attempted, paper complete | EKS/minikube as if required |

**Pass guideline:** weighted score ≥ 70, both percentages computed, and `-Xmx512m` on a 512 MiB limit is rejected.
