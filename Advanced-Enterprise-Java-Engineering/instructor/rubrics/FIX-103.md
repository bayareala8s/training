# Rubric — FIX-103 Refactor deliberately poor Java code

Do not award high Diagnostic for a guess that “the code is messy” without naming swallows, raw types, or mutable leftovers. A lucky rewrite that matches `CleanPaymentValidator` without a defect inventory is capped on Diagnostic method.

| Dimension | Weight | 100 | 60 | 20 |
|---|---|---|---|---|
| Technical accuracy | 25% | Typed API; BUILD-102 outcomes; `compareTo`; exact currencies | Reformats but leaves one of: `double`, `==` on strings, public `lastOk` | Behavior still lies on null amount |
| Diagnostic method | 20% | Written inventory of swallows, raw types, null-unsafe, God method, identity compares | Lists “bad style” without failure effect | No inventory |
| Production awareness | 15% | Shared instance state called out as future race; reasons stable | Mentions production vaguely | Treats fields as fine for a singleton |
| Trade-off analysis | 15% | Says what they extracted and what they left as one class | “I just cleaned it” | None |
| Security / reliability | 10% | No `catch (Exception)`; fail closed on null | One broad catch remains | Returns `true` after errors |
| Communication | 10% | Five-bullet defect list for a reviewer | Bullets are smells only | No write-up |
| Efficiency | 5% | Dropped scratch `List`/`Map` | Harmless leftovers | Still allocates scratch per call without need |

**Pass guideline:** weighted score ≥ 70, no `catch (Exception`, no public `lastOk`.
