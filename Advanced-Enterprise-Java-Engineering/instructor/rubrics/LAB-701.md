# Rubric — LAB-701 Observe JVM memory

Score each dimension 0–100, then apply the weight. A lucky paste of a blog `jcmd` sample without a pid or NMT categories is not a high Diagnostic or Technical score.

| Dimension | Weight | 100 | 60 | 20 |
|---|---|---|---|---|
| Technical accuracy | 25% | Real `GC.heap_info` plus NMT committed for Heap, Class, Thread, Code, GC, Internal, Total; used vs committed distinguished | Heap excerpt plus two NMT lines; categories blurred | Heap-only folklore or invented megabytes |
| Diagnostic method | 20% | Pid, start flags, and NMT-at-boot recorded; wrong-pid / NMT-disabled handled | Ran jcmd; missing flags or pid | Opened `solutions/` first; no process |
| Production awareness | 15% | BayPay Path A or B; same JVM rules on `Pay1`; no AWS; Module 7 is observe | Mentions payment-service without flags | Treats as a generic blog; recommends a cluster |
| Trade-off analysis | 15% | Heap vs RSS vs NMT; why NMT is a lab flag not a required prod default | One honest “reserved ≠ committed” | No trade-off |
| Security / reliability | 10% | No heap dump of customer data; no secret env in the paste | Harmless extra diagnostics | Publishes a dump or credentials |
| Communication | 10% | Worksheet heap + NMT readable in five minutes | Incomplete excerpt | Empty worksheet |
| Efficiency | 5% | One process, `$0`, Path A acceptable | Extra unused tools | Cloud or JFR GUI as if required |

**Pass guideline:** weighted score ≥ 70 and NMT is more than the Java Heap line.
