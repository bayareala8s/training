# Rubric — DR-1403 Regional outage tabletop

**Type:** ARCHITECT (tabletop)  
**Weights:** Technical accuracy 25% · Diagnostic method 20% · Production awareness 15% · Trade-off analysis 15% · Security / reliability 10% · Communication 10% · Efficiency 5%

The compact TRUST.md numbers in the student lab are a *post-attempt* hint. Students may change RTO/RPO **with justification**. A page that applies `us-east-1` or fails over to `dmgr-east` must not outscore a paper tabletop.

| Dimension | 5 | 3 | 1 |
|---|---|---|---|
| Technical accuracy | Payments vs reporting RTO/RPO; ND **not** a target; named pattern (pilot light / warm standby / backup-restore) | Numbers present; pattern thin | Fail over to `PaymentCluster`; one RTO for everything with no argument |
| Diagnostic method | Started from TRUST.md; argued deltas; 99.99% vs DR separated | Pasted the starting table only | Opened `solutions/` first |
| Production awareness | No `us-east-1` apply; no NAT/EKS/RDS apply; first 60 minutes refuse a hope DNS flip | Mentions paper secondary | Applied a second-region stack or recommended ND as bunker |
| Trade-off analysis | Pattern losers written; active-active split-brain named if they considered it; idle cost of warm standby | One honest trade-off | “Always hot-hot” with no RPO |
| Security / reliability | Idempotency for `c1402b22-…1402`; no PAN in the replica; TLS stays on | Mentions retries | Stores PAN or disables TLS “for DR” |
| Communication | PF-dr.md a Staff engineer could run the next tabletop from | Readable table, thin runbook | Fragment notes |
| Efficiency | 60–90 minutes, complete PF-dr.md | Complete but unfocused | Incomplete worksheet |

A recommendation to apply `us-east-1`, NAT, EKS, or multi-AZ RDS for this lab caps Production awareness at 1 regardless of table quality. Failover to `BayPayCell` / `dmgr-east` caps Technical accuracy at 1.

**Pass guideline:** weighted score ≥ 70, split payments vs reporting, ND refused, pattern named, idempotency addressed, no live second-region apply.
