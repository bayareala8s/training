# Q-04 — Module 4 quiz

Eight questions. Attempt each before you open the spoiler. Explanations match `Q-04.json`.

---

**1.** In BayPay’s payment-service, which type is actually a Jakarta servlet?

- A. `PaymentController`
- B. `DispatcherServlet`
- C. `PaymentApplicationService`
- D. `PaymentRepository`

**2.** Which pairing is the best Spring → Jakarta mapping for BayPay’s write path?

- A. `@RestController` ↔ JTA; `@Transactional` ↔ JAX-RS
- B. `JpaRepository` ↔ `EntityManager`; `@Transactional` ↔ JTA demarcation
- C. `application.yml` ↔ `EntityManager`; `JpaRepository` ↔ JNDI
- D. Spring IoC ↔ JMS; `ApplicationEventPublisher` ↔ CDI only

**3.** Hikari on `pay-prod-east-2` shows active 50 / max 50 and 41 waiters. Database CPU is 19%. What does this establish?

- A. PostgreSQL is down.
- B. The JVM heap is exhausted.
- C. This instance’s pool is exhausted; the cause is not yet proven.
- D. You must raise `maximum-pool-size` to 200 immediately.

**4.** A Hikari leak-detection line appears in logs. How should an on-call engineer treat it?

- A. As proof the root cause is a connection leak.
- B. As a candidate: confirm checkout age, stacks, and whether connections return.
- C. As a reason to disable leak detection in production.
- D. As evidence the JNDI name is wrong.

**5.** `POST /api/v1/payments` returns 201 with status `COMPLETED`, but `ledger_transactions` has no row for that payment id. What class of failure is this until proven otherwise?

- A. Load-balancer TLS mismatch
- B. Connection pool exhaustion
- C. A transaction-boundary split between status and ledger
- D. Missing `HttpSession` replication

**6.** Why should a new BayPay service not look up `jdbc/baypay` from a traditional WAS cell JNDI tree as its default design?

- A. JNDI cannot represent a DataSource.
- B. Spring Boot cannot use a DataSource.
- C. Traditional WAS ND is a source estate to modernize from, not a greenfield runtime.
- D. JNDI names are illegal in Kubernetes.

**7.** Why does BayPay’s payment API avoid `HttpServletRequest.getSession(true)`?

- A. Jakarta EE forbids sessions.
- B. The conversation is the `Idempotency-Key` plus rows in the database; a session would force affinity or replication.
- C. Spring MVC cannot read cookies.
- D. Sessions are only available on WebSphere ND.

**8.** A deploy adds `REQUIRES_NEW` on `PaymentPostingService.postAuthorized` while `create()` stays `@Transactional`. What is the risk?

- A. The HTTP thread can no longer run filters.
- B. Payment `COMPLETED` can commit while the ledger unit rolls back independently.
- C. JNDI lookups start failing.
- D. Hikari automatically sets max pool size to 1.

---

<details>
<summary>Spoiler — answers and explanations</summary>

1. **B.** `DispatcherServlet` is the servlet. Controllers are handlers.
2. **B.** Repositories wrap `EntityManager`; `@Transactional` is demarcation.
3. **C.** Exhaustion is proven; cause is not. The database is not “down.”
4. **B.** Threshold crossed ≠ closed RCA.
5. **C.** Status and ledger disagreed after an HTTP success.
6. **C.** Learn JNDI for Module 5. Do not grow traditional WAS as greenfield.
7. **B.** Stateless API; money lives in tables.
8. **B.** Two independent commits — INCIDENT-403’s mechanism.

</details>
