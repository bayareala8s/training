### Q-05-08

PMI on PaymentCluster shows the WAS JDBC pool at 50/50 and web-container threads waiting. Database CPU is 18%. What is established?

- A. The database process is down
- B. This cluster’s pool is exhausted; the cause (leak, shared reporting, hung checkout) is not yet proven
- C. You must set `maxConnections` to 500
- D. The IHS plugin certificate expired

---

<details>
<summary>Spoiler — answers and explanations</summary>

1. **B.** DMGR is admin plane. Already-started members keep serving.
2. **C.** Node agent syncs config. Application servers are separate JVMs.
3. **B.** Shared cell bind = shared pool and shared outage.
4. **B.** TCP-up is not payment-ready.
5. **C.** Stateless API; money is in tables.
6. **B.** Install ≠ distributed same edition on every member.
7. **C.** Do not grow traditional ND as greenfield.
8. **B.** Exhaustion is a symptom. Low DB CPU is not “Postgres down.”

</details>
