# Submission Checklist — Lab 01: Architecture Operating Model

**Case study:** NorthStar Financial Services (fictional)  
**Use before BayLearn upload**

---

## Title block

- [ ] Course + Module 01 labeled  
- [ ] Student name / cohort  
- [ ] Fiction notice: NorthStar is fictional  

## Mission

- [ ] ≤½ page  
- [ ] Tied to NorthStar outcomes  
- [ ] States what EA owns  
- [ ] States what EA does **not** own  

## Operating model

- [ ] Structural option chosen (central / federated / hybrid)  
- [ ] Rejected alternatives and accepted risks documented  
- [ ] Diagram shows enterprise vs BU vs platform/security/data boundaries  

## Decision rights & RACI

- [ ] Decision classes defined (≥4)  
- [ ] Decision rights summary table present  
- [ ] RACI covers ≥8 activities  
- [ ] Exactly one **A** per row  
- [ ] BU architects appear intentionally (not ignored)  
- [ ] Security and/or Data appear on relevant rows  

## Principles

- [ ] Count is 8–10  
- [ ] Each has statement, rationale, implications, exceptions, signals (or equivalent template fields)  
- [ ] Not a vendor/technology shopping list  
- [ ] At least one principle addresses security/resilience **or** implications consistently include it  
- [ ] Exception path is usable (not six-signature theater)  

## Engagement model

- [ ] Consult / collaborate / govern described  
- [ ] Entry path + rough SLA  
- [ ] ARB triggers **and** non-triggers (or justified no-ARB)  

## Risk register

- [ ] ≥5 risks  
- [ ] Includes architecture-function risks (bypass, capacity, adoption)—not only outages  
- [ ] Likelihood/impact and owner present  

## Quality pass

- [ ] CIO 10-minute skim test passed (peer or self)  
- [ ] Trade-offs explicit somewhere in the pack  
- [ ] Files named `M01_<Artifact>_<LastName>.<ext>`  

## Stretch (optional)

- [ ] Only after core checklist is complete — see `stretch-objectives.md`
