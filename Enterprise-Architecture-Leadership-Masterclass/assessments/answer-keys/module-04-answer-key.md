**Explanation:** Target state is a coherent future landscape (capabilities, patterns, controls, operating model)—not a full instance inventory, vendor catalog, or Gantt chart.  
**LO:** LO-4.1 · **Difficulty:** Easy · **Category:** Target state

### Q2 — Answer: B

**Explanation:** Without constraints and non-goals, the target cannot be funded or challenged; it is vision theater. AI timing is secondary; the structural flaw is missing constraints.  
**LO:** LO-4.1 · **Difficulty:** Medium · **Category:** Target state

### Q3 — Answer: C

**Explanation:** High coupling + regulatory SoR + rewrite cost ⇒ retain with replatform waves. Big-bang replace/retire is unrealistic for StarCore in year one.  
**LO:** LO-4.2 · **Difficulty:** Medium · **Category:** Modernization

### Q4 — Answer: B

**Explanation:** Duplicate capability ⇒ consolidate to survivor and retire loser. Retaining both avoids politics but preserves cost. Rehost/refactor both does not remove duplication.  
**LO:** LO-4.2 · **Difficulty:** Medium · **Category:** Modernization

### Q5 — Answer: B

**Explanation:** “Migrate to cloud” is a destination, not a disposition. Require one of the seven strategies. Module 05 deepens cloud; it does not ban thinking now.  
**LO:** LO-4.2 · **Difficulty:** Medium · **Category:** Modernization

### Q6 — Answer: B

**Explanation:** Transition architecture specifies interim landscape and observable exit criteria—not sprint tasks or vendor SOWs.  
**LO:** LO-4.3 · **Difficulty:** Easy · **Category:** Transitions

### Q7 — Answer: C

**Explanation:** Good exits are measurable and dated (reconciliation thresholds, write freeze). PMO status and feelings are not architecture exit criteria; endless dual-write is anti-exit.  
**LO:** LO-4.3 · **Difficulty:** Medium · **Category:** Transitions

### Q8 — Answer: B

**Explanation:** Undated “temporary” bridges become permanent cost/complexity and block consolidation benefits.  
**LO:** LO-4.3 · **Difficulty:** Hard · **Category:** Transitions

### Q9 — Answer: B

**Explanation:** Everything starting Month 1 ignores capacity and dependencies—weakest for funding. The other options show sequencing discipline.

**Explanation:** Funding cuts require renegotiated outcomes and re-sequencing. Hiding scope, cutting guardrails first, or outsourcing strategy to a vendor are leadership failures.  
**LO:** LO-4.4 · **Difficulty:** Medium · **Category:** Roadmaps

## Scenario guidance

### S1 — Strong response includes

- Consolidate to an API/event platform path; retire redundant file hubs after drain  
- New partner volume on API first; legacy volume drained with dated bridges  
- Primary risk of rehosting all three: encodes duplication/debt in cloud, little consolidation value  
**Accept variants** that pick a survivor file hub short-term if API platform is funded—must still retire losers.

### S2 — Strong response includes

- Dual-write with reconciliation + identity/audit evidence for Raj  
- Avoid full campaign freeze via strangler/canary cohorts for Elena  
- Golden record stewardship in parallel or thin slices—not a multi-year rewrite gate before any CRM progress  
- Exit to C: write freeze on loser, error thresholds met, migration % met  

### S3 — Strong response includes

- Phase 0 guardrails (Raj) before/at start of CX builds  
- CX win by Month 9 via onboarding strangler / partner API on foundation  
- Speculative AI → non-goal or late phase after governance/data readiness  
- Business language: protect downside and enable CX; AI without controls is cost+risk

## Discussion facilitation notes

### D1

Look for: honesty about loser path; migration support; exec decision record; refuse dual-retain as default; empathy without abandoning consolidate principle.

### D2

Look for: risk-first when control gaps threaten license-to-operate / material outage; CX-first when controls are “good enough” and revenue/CX mandate dominates; wrong-balance signals = rising incidents vs stalled cycle-time KPIs.
