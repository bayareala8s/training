# Instructor Guide — Module 02: Business Architecture and Capability Mapping

**Audience:** BayLearn instructors  
**Student materials:** modules/, labs/, assessments/ (non-key)  
**Classification:** Instructor-only when combined with reference solutions

---

## 1. Module purpose

Equip students to translate NorthStar strategy into a durable capability language, value-stream overlays, and investment heatmaps that guide later portfolio and roadmap work—without premature solutioning.

## 2. Learning objectives

1. Translate strategy themes into architecture priorities, constraints, and investment questions.
2. Build Level 1–2 capability maps with ownership and capability type.
3. Map value streams to capabilities and identify architecture-relevant friction.
4. Produce outcome-traceable heatmaps linking stakeholders, KPIs, and investment themes.

## 3. Prerequisites

Module 01 concepts; NorthStar case study baseline; capability / value-stream / heatmap templates skimmed.

## 4. Estimated timing (120 minutes)

| Segment | Minutes |

| Business scenario and Lesson 2.1 | 15 |

## 5. Opening business scenario

NorthStar ExCo wants cost, CX, speed, and resilience simultaneously. Acquired LOBs defend local platforms. The CIO asks for an “architecture priority list.” Facilitate the class into asking capability and outcome questions before listing systems.

## 6. Lesson flow

1. Strategy → outcomes → capabilities bridge (forbid solution lists for 10 minutes).
2. Capability definition drill: fix 5 bad labels as a room.
3. Demo a partial NorthStar L1 map + one L2 expansion + onboarding stages.
4. Lab: full student map + heatmap + value-stream overlay.
5. ARB-style review of 1–2 maps; assignment briefing.

## 7. Questions to ask

1. Is that a capability, a system, an org, or a project?
2. Who is accountable for outcomes if this capability fails—not who runs the tickets?
3. What evidence supports that heatmap color?
4. If we only fund one uplift, which stakeholder loses—and is that acceptable?

## 8. Whiteboard sequence

See `whiteboard-plan.md`. Summary:

1. Strategy themes → KPIs
2. L1 capability clusters
3. Onboarding value stream with friction sticky notes

## 9. Demonstration steps

1. Draft 10–12 L1 names live; reject two system-named proposals.
2. Classify 3 capabilities as Core/Supporting/Commodity with trade-off talk.
3. Overlay Customer Onboarding stages; mark two frictions and one investment theme.

## 10. Break points

- After concept block (~35 min)
- Mid-lab check (~75 min)

## 11. Lab facilitation

See `lab-facilitation-guide.md`.

**Lab goal:** Produce a usable NorthStar capability map, onboarding overlay, and heatmap narrative.

**Timebox rule:** Protect the last 25 minutes for review + assignment briefing even if labs are incomplete.

## 12. Common student issues

| Issue | Facilitation response |
| ----- | --------------------- |
| Map mirrors org chart | Ask: “If we reorganize, does this still hold?” Rewrite names. |
| All capabilities Core | Force a commodity example (HR/Finance) and a supporting platform. |
| Heatmap without evidence | Require one evidence bullet or lower confidence to Low. |
| Diving into applications | Park on “Module 03 parking lot” board. |

## 13. Debrief questions

1. Which naming fight taught you the most?
2. Where is friction primarily data vs. ownership?
3. What will Module 03 get wrong if this map is weak?

## 14. Assignment briefing

Students deepen the lab into an executive-ready capability investment brief (see assignment). Emphasize trade-offs and KPI traceability. Rubric: business alignment and trade-off analysis weighted heavily; security/resilience lightly but not ignored for onboarding/identity.
