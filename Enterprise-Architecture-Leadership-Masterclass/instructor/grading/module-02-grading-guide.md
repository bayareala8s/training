# Grading Guide — Module 02

**Applies to:** Lab 02 + Module 02 assignment  
**Rubric:** Standard architecture rubric + `assessments/rubrics/module-02-rubric.md`  
**Case study:** NorthStar Financial Services (fictional)

---

## What to look for

| Signal | Proficient+ | Developing |
| ------ | ----------- | ---------- |
| Capability purity | Org/system-independent names | System/team names |
| Coverage | Customer, payments, partner, risk, platforms represented | Narrow IT-only map |
| Types | Mix of Core/Supporting/Commodity with rationale | All Core |
| Ownership | Business-accountable owners | “IT” / “EA” as owners |
| Value stream | Stages + friction + capability overlay | Process laundry list |
| Heatmap | Legend, evidence, confidence | Decorative colors |
| Trade-offs | At least one defended delay/sequencing choice | “Do everything” |

## Suggested score anchoring

- **4 (Excellent):** Executive-ready; clear KPI traceability; sharp top investments; assumptions explicit.
- **3 (Proficient):** Usable map; minor naming/ownership issues; heatmap mostly evidenced.
- **2 (Developing):** Partial map; conflates systems; weak outcomes.
- **1 (Incomplete):** Unusable / missing major deliverables.

## Early-module security/resilience expectation

Do not expect full threat models. Do expect identity, KYC, and monitoring stages to appear in onboarding—and for students not to propose unconstrained data sharing across partners.

## Feedback comment bank

- “Rename X—this reads as an application.”
- “Who is accountable for the business outcome if this capability fails?”
- “Cite evidence for the amber score or lower confidence.”
- “Pick three investments; ten Priority-1s is none.”
